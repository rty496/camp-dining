# Їдальня табору

Сайт для розсадки загонів у їдальні: гіди записують загін на їжу, система сама призначає столи, офіціанти бачать на карті залу, які столи накривати, кухня — скільки порцій і на котру годину.

Два режими зберігання даних (вибирається автоматично):
- **на Vercel** — у базі Upstash Redis (див. розділ «Розгортання на Vercel»);
- **на своєму комп'ютері/сервері** — у файлі `data/db.json`, база не потрібна.

## Запуск

Потрібен Node.js 18 або новіший.

```bash
npm install
npm start
```

Відкрийте `http://localhost:3000`. Перший вхід: логін **admin**, пароль **admin123** — система одразу попросить його змінити.

Щоб телефони персоналу відкривали сайт, комп'ютер/сервер має бути в тій самій Wi-Fi мережі (адреса виду `http://192.168.1.10:3000`) або сайт треба розмістити на хостингу (Render, Railway, VPS тощо — підходить будь-який, де працює Node.js).

Змінні середовища (необов'язкові):

| Змінна | Що робить | Типово |
|---|---|---|
| `PORT` | порт сайту | `3000` |
| `ADMIN_PASSWORD` | пароль першого адміністратора | `admin123` |
| `CAMP_TZ` | часовий пояс табору | `Europe/Kyiv` |
| `DATA_DIR` | де лежить `db.json` (локальний режим) | `./data` |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | доступ до Upstash Redis (Vercel додає сам) | — |
| `SECRET_KEY` | ключ шифрування паролів (обов'язково на Vercel) | — |

**Резервна копія** — просто скопіюйте файл `data/db.json`.

## Розгортання на Vercel

1. Запуште код на GitHub і імпортуйте репозиторій у Vercel (Add New → Project). Налаштування збірки міняти не треба — Vercel сам розпізнає Express.
2. У проєкті на Vercel відкрийте вкладку **Storage** → **Create Database** → **Upstash for Redis** (безкоштовний план) → **Connect** до цього проєкту. Vercel сам додасть змінні `KV_REST_API_URL` і `KV_REST_API_TOKEN`.
3. **Settings → Environment Variables** — додайте `SECRET_KEY`: будь-який довгий випадковий рядок (ним шифруються паролі; не міняйте його потім, інакше збережені паролі не розшифруються). За бажання — `ADMIN_PASSWORD` і `CAMP_TZ`.
4. **Deployments → Redeploy**, щоб змінні підхопились.
5. Відкрийте сайт і увійдіть `admin` / `admin123` (або ваш `ADMIN_PASSWORD`).

Як це працює на Vercel: кожен запит читає дані з Redis і записує зміни назад, одночасні зміни від різних телефонів захищені блокуванням. Замість постійного з'єднання телефони кожні 5 секунд перевіряють крихітний «номер версії» і завантажують дані, лише коли щось змінилось (поки вкладка відкрита). На безкоштовних планах Vercel і Upstash є місячні ліміти запитів — для одного табору їх зазвичай вистачає, але використання можна подивитись у кабінетах Vercel і Upstash.

Дані з локального `data/db.json` на Vercel не переносяться — акаунти треба створити заново.

## Ролі

| Роль | Що бачить і робить |
|---|---|
| Адміністратор | усе; створює акаунти будь-якої ролі, зокрема глав корпусу |
| Глава корпусу | адмін-панель: створює гідів, офіціантів, кухарів, помічників; заявки, налаштування, звіт |
| Гід (ім'я + номер загону) | записує загін на сніданок / обід / полуденок / вечерю / перекус — «зараз» або на час; змінює кількість, кличе офіціанта |
| Офіціант | карта залу: які столи накрити, скільки порцій на кожен стіл; виклики від гідів зі звуком; може пересадити загін |
| Кухар, помічник кухаря | кількість порцій на кожен прийом їжі по годинах, дієти/алергії, статус «готується / готово» |

## Як працює розсадка

- Кількість столів для загону = кількість дітей ÷ 6, з округленням вгору (12 дітей → 2 столи, 14 → 3, 20 → 4). Загони **ніколи не сидять за одним столом**.
- Карта залу як у реальній їдальні: дві колонки з проходом посередині — ліворуч 1–6, прохід, 7–12; праворуч 13–25 підряд. Схему можна змінити в «Налаштуваннях» (наприклад `1-6,8-13` і `1-13`: числа — ряди зверху вниз, пропуск — прохід).
- Загін садиться на **сусідні столи в одній колонці**; столи через прохід (6 і 7) сусідніми не вважаються. Система обирає блок, що найщільніше заповнює зал і не дробить вільне місце.
- Кожен стіл намальовано з 3 стільцями зверху і 3 знизу (сервант праворуч). Система сама вирішує, **на які стільці ставити тарілки**: парами навпроти одне одного з дальнього від серванта краю (5 дітей → стільці 1, 4, 2, 5, 3).
- Вкладка **«Роздача»** для офіціантів і кухні: на кожен час — список «стіл → скільки тарілок» по порядку номерів, суми по лівій і правій колонці (скільки нести на кожен бік), дієти, кнопка «Накрито».
- Загін отримує **ті самі столи, що й минулого разу**, якщо вони вільні — діти звикають до свого місця.
- Столи зайняті лише на час прийому їжі (тривалість задається в налаштуваннях). Загони в різний час можуть сидіти за тими ж столами.
- Порції діляться рівномірно: 14 дітей на 3 столи → 5 + 5 + 4.
- Якщо сусідніх столів немає — загін садиться на найближчі вільні (з позначкою). Якщо столів не вистачає взагалі — загін стає в чергу і отримує столи автоматично, щойно хтось піде.
- Якщо гід увечері записує на сніданок — запис іде на завтра.
- Заявки закриваються автоматично через задану кількість хвилин після кінця прийому їжі.

Кольори на карті: помаранчевий (пульсує) — накрити зараз; зелений — накрито; блакитний — бронь пізніше; сірий — вільний; 🧒 — загін уже в залі.

## Файли

- `server.js` — сервер, ролі, розсадка, живі оновлення (Server-Sent Events)
- `public/` — інтерфейс (HTML/CSS/JS без фреймворків, працює з телефона)
- `data/db.json` — дані

## Паролі співробітників

Адміністратор бачить поточні паролі всіх акаунтів у вкладці «Персонал» (👁 — показати, ⧉ — скопіювати логін і пароль, щоб надіслати співробітнику). Глава корпусу бачить паролі гідів, офіціантів, кухарів і помічників. Якщо хтось змінить свій пароль сам — адмін одразу побачить новий.

Паролі зберігаються зашифрованими; ключ — у файлі `data/secret.key`. Робіть резервну копію **обох** файлів (`db.json` і `secret.key`). Акаунти, створені до оновлення, показують «пароль невідомий» — задайте їм пароль ще раз через «Змінити».

## Столи на 7 місць

У «Налаштуваннях» → «Великі столи» впишіть номери столів, де 7 стільців (напр. `1,5,13,20,25`). На карті в них з'явиться 7-й стілець у торці стола. Розсадка рахує реальні місця: 7 дітей → один великий стіл, 13 дітей → великий (7) + звичайний (6). Тарілки діляться рівномірно, але ніколи не більше, ніж стільців за столом.
